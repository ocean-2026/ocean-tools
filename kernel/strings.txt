CatOS Executable (.ce) format
=============================
A .ce file is a 20-byte header followed by the raw image (the flat
objcopy -O binary dump of a freestanding i386 program: text + rodata +
data).  Little-endian throughout.
Header (20 bytes):
  offset  size  field
  0       4     magic      "CE01"
  4       4     entry      entry offset inside the image (must be 0)
  8       4     bss_size   bytes of zeroed bss placed after the image
  12      4     api_offset offset of the 4-byte API pointer slot
  16      4     image_size raw image bytes following the header
Loading (done by the kernel for the `run` command):
  1. the whole file is read from the FAT32 volume at CE_LOAD_BASE
     (16 MiB, far above the kernel image);
  2. the magic is verified; entry must be 0;
  3. the 20-byte header is dropped and the raw image is slid to the base;
  4. bss_size zero bytes follow the image;
  5. the address of the system-call table is stored at
     image[api_offset] (the __ce_api slot);
  6. the CPU switches to a kernel-owned 8 KiB stack;
  7. the kernel calls image offset 0 as  ce_main(argc, argv)  where
     argc/argv carry the command line from `run FILE.ce args...`
     (argv[0] is the .ce path; legacy ce_main(void) apps also work).
     ce_main returns normally or calls exit() to go back to the shell.
Building an application (on the Windows host):
  sh build_ce.sh myapp.c      # gcc -> ld (extapp/ce.ld) -> objcopy
                              # -> build/mkce.py adds the header
                              # output: extapp/bin/myapp.ce
  - the entry point must be named ce_main and sit at image offset 0
    (build_ce.sh verifies this);
  - the API pointer slot is created by declaring
        catos_api_t *__ce_api __attribute__((section(".ce_api"))) = 0;
    its offset is read with nm and stored in the header;
  - no libc: write your own string/number helpers (see ce_abi.h).
API documentation: see API.TXT in this directory.
CE compiler:       build/mkce.py   (Python, wraps the CE01 header)
                   extapp/build_ce.sh  (full compile pipeline)
CatOS System API v2.2
=====================
CE programs are freestanding i386 binaries loaded by the `run` command.
Before the entry point is called the kernel writes the address of the
system-call table into the __ce_api slot of your image.  Every app must
declare:
    catos_api_t *__ce_api __attribute__((section(".ce_api"))) = 0;
and then call the functions through __ce_api (or the CE_API() helper in
extapp/ce_abi.h).  The entry point receives the command line:
    int ce_main(int argc, char **argv)
`run /bin/app.ce a b c` gives argc=4, argv[0]="/bin/app.ce",
argv[1]="a", argv[2]="b", argv[3]="c".  A legacy ce_main(void) also
works (the arguments are ignored).  The full table (33 calls):

  Example (see extapp/netinfo.c for a complete program):
      api->net_init();
      if (!api->net_up()) { ...network adapter not ready... }
      char ip[24];
      api->net_ip(ip);                     /* "10.0.2.15" */
      api->write(ip);
      if (api->net_dns("example.com", ip) == 0) api->write(ip);
      if (api->net_ping("10.0.2.2") == 0)  api->write("alive\n");
      char buf[1024];
      int n = api->http_get("http://10.0.2.2:8080/API.txt", buf, sizeof(buf));
      if (n >= 0) { api->write(buf); }     /* n = number of bytes received */
  (QEMU user-net: guest 10.0.2.15, host loopback 10.0.2.2, DNS 10.0.2.3.
   To fetch from the host run `python -m http.server 8080` there and use
   http://10.0.2.2:8080/...  External HTTP may be blocked by the host
   network; DNS and ping are the reliable path for beginners.)

Built-in apps:
   After `format` (and at every boot as a fallback) the kernel installs
   the CE apps embedded in the ISO image onto the FAT32 volume:
     /bin/hello.ce   first program: strings, time, alloc/free
     /bin/calc.ce    calculator: run /bin/calc.ce, or one-shot with
                     arguments: run /bin/calc.ce 10 + 5  (print 15)
     /bin/sysinfo.ce system information + directory browser
     /bin/demo.ce    API demo: print_int/hex, strings, atoi, colors,
                     getch, delay
     /bin/curl.ce    tiny HTTP client; URL as argument:
                     run /bin/curl.ce http://10.0.2.2:8080/API.txt
                     (with no argument it asks for an URL)
     /bin/netinfo.ce one-shot network report: own IP, DNS lookup,
                     ping, UDP echo (see the networking section above)
   Source code for all of them lives in extapp/ (host side).
Program lookup (shell):
   Every command is resolved in this order:
     1. shell builtin (dir, cd, mkdir, touch, edit, format, run, curl,
        ping, dns, udp, netdiag, help, clear, echo, about, uname, date,
        mem, reboot, hang, color)
     2. a .ce program in the current directory
     3. a .ce program in /bin (the PATH directory)
     4. otherwise: "catos: unknown command: <cmd>"
   So from anywhere you can just type `calc`, `hello` or `netinfo`.
Examples:
   sh build_ce.sh calc.c      (see extapp/build_ce.sh)
   run /bin/calc.ce           (from the CatOS shell)
   run /bin/calc.ce 7 * 6     (print 42)
   run /bin/curl.ce http://10.0.2.2:8080/API.txt
